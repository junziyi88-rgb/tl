# 仪式化扇形抽牌设计

## 目标

在线抽牌在选定问题和牌阵后，不再立即返回随机牌面，而是依次经过“呼吸聚焦”“随机洗牌”“扇形选牌”三个阶段。用户在可拖动的 2D 扇形牌堆中亲自选择指定数量的牌；完整 78 张牌的顺序与正逆位在摊开前由服务端一次性固定。

## 用户流程

1. 用户填写问题并选择牌阵。
2. 页面进入“深呼吸…默念你的问题”，展示缓慢呼吸光环，用户主动点击“我准备好了”。
3. 页面进入“打乱牌序，随机洗牌中…”，服务端生成并保存固定的 78 张牌堆；页面至少展示一段完整洗牌动画。
4. 页面进入扇形牌桌。用户左右拖动浏览全部 78 张牌背，按牌阵需要依次点击选牌。
5. 选中的牌上浮并进入已选计数；最后一张选择后，服务端按固定牌序映射牌面并进入现有逐张翻牌流程。
6. 后续 AI 解读、保存记录和分享流程保持不变。

## 视觉与动效

- 保留现有深紫黑、旧金与羊皮白色系。
- 呼吸页以一个缓慢扩张的月相光环作为唯一视觉焦点。
- 洗牌页使用三张牌背交错移动，避免引入视频、Canvas 或 3D 依赖。
- 扇形牌桌是本次唯一标志性元素：牌背沿下弧线重叠排列，拖动时仅使用 `transform`，选中牌向上抬起并出现金色描边。
- 尊重 `prefers-reduced-motion`，减少或关闭循环动效。

## 架构

- 新增纯前端扇形布局工具，负责中心位置限制、可见窗口和每张牌的位移/旋转参数。
- 新增 `draw_sessions` D1 表，保存成员、问题、牌阵快照、完整牌堆和创建时间。
- `POST /api/draw` 支持三个动作：`prepare` 创建固定牌堆，`select` 将用户选择的序号映射为牌面并创建 AI 草稿，`physical` 为线下牌面创建 AI 草稿。
- 浏览器在摊牌阶段只知道牌背序号，不接收完整牌序；点击结果由服务端根据已保存牌堆决定。
- 最终 AI 草稿 ID 同时作为在线记录幂等键，修复当前页面未采用服务端 `draftId` 的衔接问题。

## 边界与错误处理

- 选牌序号必须为 0–77 的不重复整数，数量必须与牌阵牌位数一致。
- 牌堆会话只能由创建者访问。
- 洗牌请求失败时保留问题和牌阵，并允许重试。
- 拖动超过阈值时不触发点击，防止浏览牌堆时误抽。
- 键盘左右键可以浏览，按钮保留可见焦点和可读标签。
- 线下抽牌不经过呼吸、洗牌和扇形页。

## 测试

- 完整牌堆包含 78 张唯一牌，正逆位合法。
- 按用户选择顺序生成牌面，牌位与牌阵一一对应。
- 重复、越界或数量错误的序号被拒绝。
- 扇形中心值被限制在可浏览范围，可见窗口在首尾都覆盖正确牌序。
- 现有牌阵、AI 解读、保存和构建测试继续通过。
