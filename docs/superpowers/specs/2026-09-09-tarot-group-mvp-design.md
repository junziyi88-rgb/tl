# 微信群多人塔罗记录工具 MVP 设计

## 目标

构建一个适合 50 人以内微信群共同使用的移动端网页。网站只有一个固定公共空间，群成员通过同一个固定网址进入，以昵称发布塔罗记录，并查看所有人的完整记录。抽牌必须先填写问题，支持九个内置情感/关系牌阵和本人可见的临时、自建牌阵，并可按需调用国内 DeepSeek 轻量模型辅助解牌。

MVP 不接入微信群机器人，不要求登录，也不提供私密记录。网页需同时支持在线随机抽牌和记录线下抽牌。

## 成功标准

- 网站部署后直接提供唯一公共空间和固定分享网址。
- 成员可输入昵称进入公共记录墙，无需注册账号。
- 最多约 50 名成员可以浏览和新增记录。
- 在线抽牌与线下选牌均可形成格式一致的公开记录，也可只完成本次占卜而不保存。
- 记录作者可以事后补充一行“真实反馈”。
- 用户可点击生成 AI 辅助解读；AI 失败不影响抽牌和记录。
- 页面在微信内置浏览器及常见手机浏览器中可正常使用。

## MVP 范围

### 公共空间与身份

- 整个网站只有一个公开共享空间，不提供创建、切换或加入房间的功能。
- 所有成员通过网站固定首页网址进入同一个记录墙。
- 成员首次进入时填写昵称；昵称及成员凭证保存在浏览器本地。
- 成员凭证用于识别和编辑本人记录，不作为安全账号体系。
- 群主另持管理密钥，可删除任意记录。
- 获得网站链接的人均可进入和查看，不额外设置密码。

### 在线随机抽牌

- 使用完整 78 张塔罗牌数据。
- 抽牌前必须填写本次主问题；空问题不能开始抽牌。
- 内置维纳斯之爱、爱的解答、心之声、他心知、恋人金字塔、情感之境、爱情十字、关系前景和友谊牌阵九个牌阵。
- 友谊牌阵按六张牌实现，右下角为第六牌位“对方期待的未来发展”。
- 洗牌与抽牌在一次提交中随机完成，同一张牌不会重复出现。
- 每张牌独立随机决定正位或逆位。
- 抽牌前显示牌背；用户逐张翻开后显示牌名、图片和正逆位。
- 翻牌结果只直接显示牌名、图片和正逆位；基础牌义只作为 AI 生成底稿，不单独暴露。

### 临时与自建牌阵

- 用户可为本次问题临时建立 1–12 张牌的牌阵，编辑名称及每张牌的小问题，并调整顺序、增删牌位。
- 临时牌阵同时支持在线随机抽牌和线下手动填牌。
- 抽牌后可选择不保存、仅保存本次记录、同时保存记录和牌阵。
- 保存的自建牌阵仅创建者可见；读取、修改和删除均要求成员编辑令牌。
- 自建牌阵绑定当前浏览器保存的成员凭证，MVP 不提供跨设备恢复。

### AI 辅助解牌

- 使用 DeepSeek 国内 API 的 `deepseek-flash` 非思考模式，仅由服务端调用。
- 应用内置 78 张牌的原创中文正位、逆位基础牌义；模型负责结合主问题、牌位小问题和牌面关系组织语言。
- 用户主动点击“AI 辅助解牌”后才调用模型；线上随机和线下手动牌面均支持。
- 每张牌输出约 100–200 个中文字，并附简短综合结论和行动建议。
- 每次抽牌最多生成三次；结果先私下预览，用户选定后可加入公开记录。
- AI 内容与“我的解读”分栏显示，个人解读改为选填，AI 内容不得冒充用户观点。
- 医疗、法律、投资、生死等问题不生成确定性结论，所有结果标注“仅供娱乐与自我反思”。
- 超时、余额不足、内容过滤或格式错误时保留抽牌和草稿，允许稍后重试。

### 线下抽牌记录

- 用户选择牌阵并按位置添加牌。
- 可按牌名搜索或从完整牌表选择。
- 每张牌可设置正位或逆位。
- 保存后的记录结构与在线抽牌一致。

### 记录内容

- 占卜主题或问题，必填。
- 抽牌方式：在线随机或线下记录，系统自动保存。
- 牌阵、牌位、牌名、正逆位，系统根据抽牌过程保存。
- 个人解读，多行文本，选填。
- AI 辅助解读，可选，由用户选定后随记录公开保存。
- 标签，可选，最多三个简短标签。
- 作者昵称与创建时间，系统自动保存。
- 真实反馈，单行文本，可留空并在事后补填或修改。

### 公共记录墙

- 默认按创建时间倒序展示全部记录。
- 卡片摘要显示作者、时间、问题、牌面缩略图、抽牌方式和标签。
- 支持按成员、抽牌方式和标签筛选。
- 进入详情后展示完整问题、牌阵、牌面、个人解读和真实反馈。
- 作者可修改问题、解读、标签和真实反馈，也可删除本人记录。
- 群主可删除任意记录。

### 微信群分享

- 首页可复制网站固定链接。
- 记录发布后生成一段简短分享文案，并提供复制按钮。
- 不调用个人微信自动发消息；由用户粘贴到微信群。

## 页面与交互

1. **昵称页**：首次进入固定首页时填写昵称；后续从本地恢复并直接进入记录墙。
2. **公共记录墙**：浏览、筛选记录，并选择“在线抽牌”或“记录线下抽牌”。
3. **问题与牌阵页**：先填写主问题，再选择内置牌阵、已保存的自建牌阵或建立临时牌阵。
4. **在线抽牌页**：洗牌、抽牌、逐张翻牌；翻牌后可生成 AI 解读并决定是否保存记录或牌阵。
5. **线下选牌页**：按牌位搜索并选择牌，设置正逆位。
6. **记录编辑页**：填写问题、个人解读和可选标签，预览后发布。
7. **记录详情页**：查看完整记录；作者可编辑一行真实反馈或其他可编辑字段。
8. **群主管理入口**：输入管理密钥后获得删除任意记录的能力。

## 系统结构

### 前端

- 移动端优先的单页 Web 应用。
- 负责公共记录墙浏览、抽牌交互、牌面展示、表单与筛选。
- 成员凭证和最近使用昵称保存在浏览器本地存储。
- 随机抽牌结果在服务端校验并随记录一次性保存，避免重复提交产生不同结果。

### 后端

- 提供记录、成员凭证和管理操作 API。
- 提供本人自建牌阵的增删改查 API，以及受限的 AI 解读 API。
- 使用托管数据库保存成员及记录。
- 通过成员编辑令牌和群主管理令牌控制操作范围。
- API 对字段长度、牌名、牌阵和正逆位值进行校验。

### 数据模型

- `Member`：成员标识、昵称、编辑令牌摘要、创建时间。
- `Reading`：记录标识、成员标识、问题、抽牌方式、牌阵快照、牌面数组、个人解读、AI 解读、标签、真实反馈、创建和更新时间。
- `CustomSpread`：牌阵标识、成员标识、名称、1–12 个有序牌位、创建和更新时间。
- `Card`：稳定牌 ID、中英文牌名、所属组别、图片路径。

牌面数组中的每项包含牌位序号、牌位名称、牌 ID 和正逆位。卡牌基础数据随应用版本发布，不允许用户修改。

## 数据流

### 在线抽牌

成员先填写问题并选择或临时建立牌阵 → 客户端请求随机牌面 → 服务端从 78 张牌中无放回抽取并随机正逆位 → 客户端逐张展示 → 用户可手写解读或点击 AI 辅助解牌 → 用户选择不保存、仅保存记录或同时保存记录与自建牌阵 → 已保存记录出现在记录墙。

### 线下记录

成员选择牌阵 → 按牌位选择牌和正逆位 → 客户端检查重复与缺失 → 用户填写问题与解读 → 服务端再次校验并保存 → 记录墙出现新记录。

### 补充反馈

作者打开本人记录 → 填写或修改单行真实反馈 → 服务端验证成员编辑令牌 → 更新记录 → 所有成员在详情页看到最新反馈。

## 错误处理

- 昵称、问题或解读为空：在当前表单内提示，不清空已填内容。
- 网络失败：保留当前输入和已抽牌面，允许重试提交。
- 重复提交：使用一次性提交标识确保只创建一条记录。
- 非作者尝试编辑：返回无权限提示，不暴露编辑令牌信息。
- 卡牌图片加载失败：显示牌名与统一占位图，不阻止记录使用。
- AI 调用失败：显示简短原因并允许重试，不清空问题、牌面、个人解读或已选 AI 版本。

## 测试重点

- 78 张牌数据完整且 ID 唯一。
- 在线抽牌数量正确、无重复，正逆位值合法。
- 九个内置牌阵及 1–12 张临时牌阵均可通过在线和线下两种方式使用。
- 自建牌阵只有作者凭证可以读取、修改和删除。
- 不保存、仅保存记录、同时保存记录与牌阵三条结束路径均正常。
- AI 每牌输出长度受限，最多生成三次，JSON 异常和上游失败时不丢失本地状态。
- 两个不同浏览器成员可看到彼此记录，但不能编辑对方记录。
- 作者可以补填一行真实反馈，其他成员立即或刷新后可见。
- 群主可以删除任意记录。
- 表单在提交失败后不丢失用户输入。
- 微信内置浏览器常见屏幕尺寸下无横向滚动和关键按钮遮挡。

## 明确不做

- 微信个人号机器人或自动群消息。
- 微信登录、手机号登录或完整账号找回。
- 私密记录、好友权限或分级可见性。
- 创建、加入或切换多个房间。
- 评论、点赞、实时在线状态和聊天。
- 自动触发 AI 解牌、无限次重新生成或将 AI 文案冒充用户解读。
- 付费、订阅、广告和数据统计后台。
- 多轮反馈时间线；每条记录仅保留一个最新的单行真实反馈。

## 后续可选增强

- 微信授权登录与跨设备身份恢复。
- 更多牌组、牌面主题和跨设备自建牌阵同步。
- 评论、收藏和月度复盘统计。
- 企业微信群官方机器人自动播报。
